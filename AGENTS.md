# AGENTS.md — consult-committee

Hermes plugin. Registers one tool: `consult_committee(question, preset?)`.
Acting model escalates hard questions; handler fans out to the reference
models of an MoA preset (default `committee`) in parallel with its own
`call_llm` calls; model synthesises (it is the aggregator). Only MoA's
settings are reused, never its runtime.

## Layout

- `__init__.py` — entire plugin: `CONSULT_SCHEMA`, `_handle_consult_committee`, `register(ctx)`, committee-preset selection, own advisor fan-out (`_run_advisors` / `_call_advisor`), profile/model identity + profile-aware log path + log block (`_log_exit`, `_format_log_block`, `_advisor_status`, `_plugin_version_text`) + advisor system message + escalation-tier prompt section (`_escalation_section` and helpers).
- `tests/` — self-contained, no live LLM, no Hermes install: `test_consult_committee.py` (handler, budget, logging, advisor system), `test_helpers_characterization.py` (pins helper behaviour; must stay green unchanged across refactors), `test_escalation_tier.py` (tier setting, prompt section, `register`), `test_versioning.py` (version/CHANGELOG/tag links), `test_docs.py` (prompts only in `escalation-prompts.md`, README length, links/anchors resolve, `--ref` never given a tag).
- `pytest.ini` — `testpaths = tests`. Canonical command: `pytest` from repo root.
- `plugin.yaml` — name/version/tools. `CHANGELOG.md` — fork history. `README.md` — short front page (what, why, install, quick start, settings; ≤150 lines, test-enforced). `GUIDE.md` — everything in depth (design, install/pinning, settings, presets, budget, escalation behaviour, call log, advisor system message, fork history). `escalation-prompts.md` — the ONLY copy of the tier prompts + tier table. `COMPARISON.md` — vs-alternatives (MoA, council, advisor, delegation) comparison. `ONBOARDING.md` — Muse routing standing order. `advisor_system.md` — bundled advisor system default.

## Handler contract (`_handle_consult_committee`)

- Lazy imports only, inside function body (mirrors Hermes call sites, avoids import cycles).
- Never raise: all paths return `tool_result` / `tool_error` JSON strings; outer `except Exception` → `tool_error("committee consultation failed: …")`.
- Validation first: empty `question` → `tool_error("question is required")` before touching Hermes modules.
- Budget: `_consultations` dict keyed by `_budget_key(kwargs)`: the dispatcher's `conversation_id` (compression-stable, shared with delegated children; Hermes' documented key for per-conversation plugin state), else `session_id`, else one process-wide bucket. Cap = `settings.max_consultations` via `_max_consultations()` (default `_DEFAULT_MAX_CONSULTATIONS = 5`, `0` disables, invalid → default). Reserve under `_lock` before the fan-out; a `finally` refunds unless a `tool_result` with ≥1 answer was built (bad preset / no models / all failed / exception / stop request cost nothing; a deadline cut with ≥1 answer is delivered and charged; discarded fallback answers count as failures). Stop request = `tools.interrupt.is_interrupted()` true on the tool thread after the fan-out (`_interrupted()`, lazy import, False when unavailable): Hermes has abandoned the call, so return a "cancelled" `tool_error`, still log the block (`outcome: cancelled …`). Both say "stop request or Hermes' tool deadline": Hermes' deadline sets the same bit, the plugin cannot tell them apart. Past cap → `tool_error("committee budget exhausted (N consultations this <conversation|session|gateway process>) …")`. Log `seq` is the process-wide `_log_seq`, taken at reserve time (none for the two exits before it).
- Preset: explicit `args.preset` > setting `preset` via `_committee_preset_setting()` (default `_DEFAULT_COMMITTEE_PRESET = "committee"`; empty/off-word → skip, as do `False` and zero: YAML 1.1 reads an unquoted `off`/`no`/`false`/`0` that way) > Hermes' rule `resolve_moa_preset(moa_cfg, None)` (`moa.default_preset` if it names an existing preset, else the FIRST preset listed). A setting naming a missing preset falls back to Hermes' rule with `preset_note` (result key + `note:` log line); an unknown explicit preset is an error. Labels: `'<name>' (committee preset)`, else `_preset_in_use(moa_cfg, explicit)` → `(name, label)`: explicit `'x'`; else asks Hermes' `normalize_moa_config` → `'<name>' (moa.default_preset)` or `'<name>' (first preset; moa.default_preset not set|'<raw>' not found)`; without it (older Hermes, test fakes) `'<raw>' (moa.default_preset)` / `'default' (no moa.default_preset set)`. Never `None`. Catch `(KeyError, ValueError)` → `unknown MoA preset: <label>`; real Hermes raises `MoAPresetNotFoundError`, a `ValueError` (fake mirrors it).
- No usable slot in the RAW config (`_has_configured_advisors`; Hermes would substitute its built-in advisors) → `tool_error("… has no reference models configured")`. The check follows Hermes' merge: raw `presets` missing/None → False even beside a flat top-level `reference_models` (Hermes keeps its built-in presets); an empty or non-dict `presets` → the flat top level is the `default` preset; else `presets[name]`, names matched stripped as Hermes does. Slots with `enabled: false` dropped; none left → `"… has every reference model disabled"`. Preset-level `enabled` is MoA's switch and is ignored.
- Fan-out: `_run_advisors(slots, _advisor_messages(question, system_text), temperature=_reference_temperature(preset), timeout=_reference_timeout(preset))` → `[(label, text)]` in slot order. One `_call_advisor` per slot in a thread pool (`_executor_class`: Hermes' `tools.daemon_pool.DaemonThreadPoolExecutor`, lazy import, so abandoned calls never block process exit; stdlib pool as fallback), each in `contextvars.copy_context()` (Hermes' usage accounting lives in contextvars): `call_llm(task=_ADVISOR_TASK="consult_committee", messages, temperature, timeout, reasoning_config=_slot_reasoning(slot), **_slot_runtime(slot))`; `_slot_runtime` = provider/model + `resolve_runtime_provider` base_url/api_key/api_mode/extra_body (bare on failure). Errors → `[failed: …]`, empty reply → `""`. `route_info={}` is passed when `call_llm` names that parameter (`_accepts_route_info`); a set `fallback_label`, or a recorded `model` other than the slot's (not `default`; a slash-bearing slot id is compared after Hermes' own `normalize_model_for_provider`, `_hermes_model_name`, and not flagged when that is unavailable; never compare providers, Hermes rewrites them), means another model answered → `[failed: advisor unavailable (…); Hermes fell back to …, answer discarded]` (`_fallback_failure`). The wait polls `_interrupted()` every `_INTERRUPT_POLL_SECONDS`; on a stop it returns at once, unfinished slots → `[skipped: stop requested]`. It also stops at `_fanout_deadline_seconds()`: Hermes' `_resolve_sequential_tool_timeout()` (lazy import of `agent.tool_executor`) minus `_TOOL_DEADLINE_MARGIN_SECONDS`, half of it when shorter than twice the margin, None (no limit) when Hermes has it disabled, 420 − margin when unavailable; unfinished slots → `[skipped: committee deadline reached after Ns]`. That is not a cancellation: the handler carries on with what answered. `_run_advisors` keeps its signature (handler tests replace it). Labels `provider:model[reasoning=x]` (`_slot_label`). `_reference_temperature` honours `0`, missing/None/bool/invalid → `0.9`; `_reference_timeout` positive number, else `900`. `_advisor_messages` prepends `{"role":"system","content":system}` when non-empty, else user-only; it is the only system message sent. Never import `agent.moa_loop`.
- Advisor system: bundled `advisor_system.md` (exact text lives in that file — never quote it here); precedence env `CONSULT_COMMITTEE_ADVISOR_SYSTEM` > GUI `advisor_system` > bundled file > hardcoded fallback; `off` disables (user-only); read lazily via `__file__`, never raises, never breaks call. Hermes writes a plugin setting only when the user saves that field (desktop GUI posts changed keys only; `save_plugin_settings` writes the keys it is given; observed v0.23.1 configs hold just `logging`), so the file wins by default. The GUI field displays the `plugin.yaml` default, not the file.
- Failure detection per advisor: `_is_failed_output` — empty, or `lstrip().lower()` starts with `[failed:` / `[skipped:` (the fan-out's sentinels, same check as Hermes' `moa_loop`) or legacy `[error`. Never substring-match `failed:` (legit answers say "build failed: …"). Partial failure OK; all-failed → `tool_error("all committee advisors failed …")`. Test fakes must use the real sentinel strings.
- Truncation: `_TRUNCATE_CHARS = 6000` per advisor + `\n[... truncated]`.
- Success payload: `{advisors: [{model, answer, failed}], answered, failed, note[, preset_note]}` where `note` instructs caller to aggregate itself.
- Escalation tier (prompt section, not the handler): `register()` registers the tool first, then, only when `getattr(ctx, "register_system_prompt_section")` is callable, section `_ESCALATION_SECTION_ID = "consult-committee.escalation-policy"`, `position="after_memory"`, `max_chars=4000`, content the callable `_escalation_section(session_info)`, inside its own try/except (warning via `_logger`, tool unaffected). Registered even when the tier is off: Hermes calls it whenever it builds a session's prompt (each new session; again after context compression and `hermes sessions refresh-prompts`, which clear the frozen snapshot; a resume restores the stored text), so setting changes apply without a restart. Hermes keeps the previous text only when the callable raises; ours returns "" instead, so a transient config failure at a rebuild drops the block from that session. `_escalation_section`: ONE outer try/except → ""; `_bind_profile_home(session_info)` sets Hermes' context-local home override to `get_profile_dir(profile_name)` only when the name is non-empty, not `default`, an existing dir and not already the ambient `_hermes_home()` (some threads lose Hermes' ContextVar), and always undoes it; `_escalation_tier_setting()` (`escalation_tier`, `plugin.yaml` `choices` dropdown: `high|medium|low` via `_text().lower()`, every non-str/unknown → `off`; no env override; never touches `max_consultations`); off → ""; `_soul_has_escalation_block(home)` (`^##[ \t]+Committee Escalation\b`, `re.M | re.I`: any text after the words, so `(medium)` and `- High` match, `Escalations` and `###` do not; read `utf-8-sig`, `errors="replace"`) → "" + one `_note_once` INFO line; `_tier_block(tier)` reads `escalation-prompts.md` beside `__file__` with the same fence regex as `tests/test_docs.py::_prompt_blocks` and matches heading `## Committee Escalation (<tier>)`; missing → "" + one WARNING. Log lines go through `_logger` (Hermes' log), never the call log, once per key (`_escalation_notes`, reset in tests): INFO SOUL-skip per home and INFO inject per (home, tier), both naming the resolved home; WARNING missing block per tier, naming the tier and `escalation-prompts.md`. Never copy prompt text into code or tests. Known limit: sessions' toolsets are not visible to sections.
- Audit log (opt-in, OFF by default): asking profile's `logs/consult-committee.log` via profile-aware `get_hermes_home()` (+ `HERMES_HOME`/`~/.hermes` fallback); fixed profile-relative default `logs/consult-committee.log` in `config_schema.log_path.default`; relative custom/env paths resolve against profile home (`~`/env expansion, absolute passthrough); enable via GUI logging=true or CONSULT_COMMITTEE_LOG path (env overrides, `off`/empty disables); GUI via `config_schema` (`logging` bool + `log_path` str). Exactly ONE block per tool call, at exit, for every exit (refusals, error, cancelled, all-failed, delivered, delivered after deadline cut). The handler fills a local `state` dict as it goes (`outcome`, `question`, `preset_label`, `preset_note`, `system`, `advisors`, `fanout`, `temperature`, `timeout`, `seq`, budget key/scope/cap) and calls `_log_exit(state)` once: on the empty-question path, on the budget-exhausted path, and in the handler's `finally` after the refund (so the `budget:` count is the post-call truth). `_log_exit` returns early when logging is off, builds the entry (UTC timestamp `YYYY-MM-DD HH:MM:SS UTC`, `_plugin_version_text()` = cached `version:` line of `plugin.yaml`, budget line, timing line) and hands it to `_maybe_log_call_text(entry, path=None)`, which writes `_format_log_block(entry)` under `_lock`. Block: header `=== ts | seq N | conversation|session ID | profile P | model M ===` (`seq` omitted for the empty-question and budget-exhausted exits, which take none; ID from `_budget_log_label`, omitted for the process bucket; other parts omitted when unknown), then labelled lines `plugin:`, `preset:` (label saying why), `note:` (only with `preset_note`), `budget:`, `timing:` (elapsed; deadline, advisor timeout, temperature only once the fan-out was reached), `outcome:` (fixed vocabulary, always states the budget effect; see GUIDE), then `Q (N chars[, first M shown]): …` (cap `_QUESTION_LOG_CHARS = 4000`), `S: …` when a system role is sent, then `--- advisor i of N: <label> ---` sections, each with `status:` from `_advisor_status(answer, chars)` (answered (N chars[, truncated from M chars]) / failed: … / fallback discarded: … / skipped: … / empty reply); the answer body is printed only for answered advisors, exactly as delivered (after the 6000-char cap). No `[FAILED]` marker, no `answered: N failed: M` line, no `cancelled:` line. Log I/O and every log helper never raise.

## Conventions

- One required param (`question`); `preset` optional. Keep `CONSULT_SCHEMA.description` policy-neutral: what the tool does, what advisors can't do, question format, budget, and a one-sentence fallback for when no system-prompt rule exists. When-to-call policy (triggers, tripwires, frequency) belongs in the caller tier blocks (`escalation-prompts.md`, explained in `GUIDE.md`), never in the schema: it is in context for every profile and would override a Low tier. `TestSchemaDescription` enforces this.
- Helpers that must never raise: plain logic inside ONE outer `try/except Exception` returning the documented fallback. No nested guards around operations that cannot raise. Reuse `_text()` (strip, None → ""), `_one_line()` (log fields) and `_hermes_home()` (get_hermes_home → $HERMES_HOME → ~/.hermes) instead of re-implementing them. The handler calls helpers directly; they own their own safety.
- No keys / model names in plugin. No new deps. European conventions, stdlib only.
- Never quote volatile file defaults (e.g. `advisor_system.md` text) in agent docs — reference the file, so wording tweaks don't touch `AGENTS.md`.
- Update `CHANGELOG.md` (Keep a Changelog) + `plugin.yaml` version on behaviour change; add tests for every fix (see `TestDefaultPresetResolution`, `TestCommitteePreset` as templates).
- Versioning: plain SemVer `MAJOR.MINOR.PATCH` from `0.2.0` on (no more `-fork.N`; it is invalid PEP 440, which Hermes uses to compare versions). Unreleased work goes under `## [Unreleased]`.
- Release: (1) move `[Unreleased]` entries to `## [X.Y.Z] — YYYY-MM-DD`, set `plugin.yaml` `version: X.Y.Z`, add the `[X.Y.Z]:` compare link and repoint `[Unreleased]:`; (2) `pytest` green (`tests/test_versioning.py` enforces version/heading/link consistency); (3) commit, then `git tag -a vX.Y.Z -m "consult-committee X.Y.Z"` on that commit; (4) push the commit and the tag. Never move or delete a pushed tag; fix forward with a new patch release.
